## 已凍結的重要決策

1. v2 使用 `/api/v2`；`/api/v1` 只在過渡期保留。
2. v2 正式寫入必須使用支援資料版本的 v2 客戶端。
3. 可修改資源使用 `row_version`＋`If-Match`；衝突回傳 409，不自動覆蓋。
4. PostgreSQL schema 由 7 逐版升至 8～12，不允許一次大改或跳版。
5. LINE Bot 維持最小權限；綁定資料仍在 Bot 獨立加密 SQLite。
6. 不做完整離線正式資料同步、不做 GIS／OCR／AI、不增加付費雲端相依。
7. 正式切換前必須有已驗證完整備份、異地副本與隔離還原演練。

## 尚待家中主機實機完成

以下不是開發工作區可安全代替的項目，因此仍是第二階段開始前的外部關卡：

- 在家中正式主機建立最新 PostgreSQL＋附件完整備份。
- 建立異地副本並核對 SHA-256。
- 在隔離 PostgreSQL 還原並驗證登入、筆數、關聯與附件。
- 記錄演練日期、備份檔名與結果，不記帳密或 DSN。

## 第二階段入口

第二階段只做非破壞性平台骨架：

1. 實作 `GET /api/v2/system/capabilities`。
2. 實作標準成功／錯誤外殼、Request ID 與 v1 棄用標頭。
3. 建立 schema 8 migration 檔與隔離資料庫測試，不套用正式資料。
4. 先在持分更新加入 `row_version` 衝突測試，再擴展到其他資源。
5. 更新桌面測試客戶端完成能力協商；正式 v1.8.2 包維持不變。
