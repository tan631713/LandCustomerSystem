## 3. v2 必增自動測試

### API v2

- 能力協商、最低版本與維護狀態不洩漏內部環境。
- 標準成功／錯誤外殼及 Request ID。
- v1 棄用標頭與 v2 successor link。
- 游標分頁穩定、不重複、不遺漏、範圍隔離。
- 409 樂觀鎖：桌面／手機同時更新不得靜默覆蓋。
- `/api/v1` 過渡政策及過舊客戶端寫入阻擋。

### schema 8～12

- 每版可從上一版升級且可重跑檢查，不可跳版。
- migration 中途失敗完整回滾。
- 核心表筆數、外鍵、加密值與 identity 游標不變。
- workflow 狀態與轉移規則有效。
- 通知投遞、回條、背景工作、稽核及升級批次唯一條件有效。
- 正式 `postgres/schema.sql` 只有經審核 migration 才能更新。

### 權限

- Admin、Editor、Viewer 的每個端點正向與反向測試。
- district／section／project 資料範圍套用在 SQL、彙整、匯出、附件與全域搜尋。
- 身分證前四後一，地址、電話與聯絡內容依角色遮罩。
- LINE Basic／Business／Full 的指令與快速按鈕同時阻擋未授權功能。
- 背景服務不能使用互動登入或讀取無關資料。

### 附件

- 拍照、多選、壓縮、原檔、縮圖、下載、分類、說明及角色限制。
- SHA-256 正常、缺檔、內容不符、不可讀及孤兒檔案。
- 備份／還原後附件數、大小、雜湊及資料庫關聯一致。
- 外部連結不誤標為已納管或已備份。

### 跨端

- 桌面寫入，手機及 LINE 重新查詢取得同一版本。
- 手機新增聯絡／追蹤／附件，桌面立即可見。
- LINE 通知回條，桌面通知中心可見且權限正確。
- 舊 PWA 快取不保留 v1 寫入程式。
- 公司客戶端從正確家中主機取得 CA 並釘選。

### 升級與回復

- 升級前檢查缺備份、空間不足、服務執行中、憑證錯誤及版本不符。
- 在隔離複本完成 schema 7→12、筆數／關聯／附件核對。
- 每一關失敗都停止，不進入下一關。
- v2 冒煙失敗後能還原 schema 7 與 v1 程式，v2 Token 失效。

## 4. 五條真實驗收流程

1. Excel 匯入 → 重複預覽 → 建立地主／土地／持分 → 桌面與手機查詢一致。
2. 建立案件 → 指派負責人與任務 → 手機更新下一步 → LINE 收到受權限限制的提醒。
3. 手機拍照上傳 → 桌面預覽／分類 → 完整性掃描 → 完整備份及隔離還原。
4. 桌面與手機同時修改同一持分 → 後送端收到 409 → 人工重新載入或合併。
5. 建立追蹤 → 到期通知 → LINE 完成回條 → 桌面通知中心與稽核可追溯。

## 5. 正式門檻

- 單元、整合、API、Qt、PWA、LINE、備份還原及封裝測試全部通過。
- 不接受忽略的阻斷級或高風險失敗。

- 測試報告只含脫敏資料，不得包含正式帳密、DSN、Token 或地主內容。
