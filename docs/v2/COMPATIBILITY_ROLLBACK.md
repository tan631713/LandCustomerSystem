# v2.0 相容、升級與回復規格

## 1. 原則

- 正式切換前，v1.8.9 繼續是唯一正式伺服器。
- v2 開發、schema 遷移及驗收只在隔離複本執行。
- v2 伺服器過渡期保留 `/api/v1`，但舊客戶端不可永久保有寫入權。
- 回復不是把新資料硬塞回舊 schema；正式切換觀察期內如需回復，必須停止 v2 寫入並還原切換前完整備份。

## 2. 客戶端相容政策

| 元件 | 目前版本 | v2 測試期 | v2 正式切換後 |
|---|---:|---|---|
| 公司筆電 | v1.8.2 | 可連 v1；v2 測試環境只讀 | v2.0 才可寫入；v1.8.2 僅有限讀取過渡 |
| iPhone PWA | v1.8.9 隨附 | 使用 v1 正式頁；另開 v2 測試入口 | 由 v2 伺服器更新並清除舊寫入快取 |
| LINE Bot | v0.30.0 | 繼續唯讀 v1；v2 Bot 連測試 API | v0.30.0 只讀過渡；新案件／通知要求 v2.0 |
| 家中桌面 | v1.8.9 | 不連 v2 測試資料 | 正式包 v2.0 |

過渡期長度由正式切換會議決定；契約預設 14 天。過渡期結束後 `/api/v1` 回傳 `LCS_CLIENT_UPGRADE_REQUIRED`，不得靜默寫入。

## 3. 升級前關卡

每項都必須留下 `upgrade_batch` 與檢查結果：

1. 版本：伺服器 v1.8.9、桌面 v1.8.2、LINE v0.30.0。
2. PostgreSQL schema 7，且不存在失敗或未完成 migration。
3. `pg_dump`、`pg_restore --list`、附件 manifest 及 SHA-256 正常。
4. 至少一份異地副本可讀，剩餘磁碟空間足夠容納兩份完整資料。
5. owners、lands、ownerships、案件、任務、附件、回收桶與操作紀錄無孤兒。
6. NetBird、HTTPS 私人 CA、憑證有效期及 8732／8733 服務正常。
7. 232 項 v1 測試及 v2 遷移測試全部通過。
8. 目前沒有匯入、備份、附件上傳或批次操作正在執行。

## 4. 隔離複本演練

```text
建立正式完整備份
        ↓
在隔離 PostgreSQL 建立複本
        ↓
逐版套用 schema 8 → 9 → 10 → 11 → 12
        ↓
核對筆數、關聯、版本、遮罩、附件與權限
        ↓
啟動 v2 API 與測試客戶端
        ↓
執行五條真實工作情境
        ↓
輸出遷移、效能與驗收報告
```

隔離演練不得使用正式附件路徑寫入；附件庫必須複製到測試目錄或唯讀掛載。

## 5. 正式切換

1. 公告維護並停止桌面、手機與 LINE 寫入。
2. 等待所有背景工作結束，撤銷所有 Token。
3. 建立「切換前」PostgreSQL＋附件完整備份及異地副本。
4. 記錄版本、schema、表筆數、關聯數、附件數／總大小／雜湊摘要。
5. 逐版套用已在複本驗證的 migration；每版單獨交易與核對。
6. 啟動 v2 API，只允許管理員冒煙測試。
7. 家中桌面、公司筆電、iPhone、LINE Bot 依序測試。
8. Go／No-Go 全部通過後才恢復一般使用者寫入。
9. 進入 7 天觀察期；保留切換前備份、舊程式包及回復腳本。

## 6. 立即停止條件

發生任一項即 No-Go：

- migration 失敗或 schema 版本不連續。
- 任何核心表筆數不符、關聯孤兒或加密資料無法解密。
- 附件缺檔、SHA-256 不符或備份無法列出內容。
- Admin、Editor、Viewer、LINE 任一越權。
- v1 保留功能的阻斷級回歸失敗。
- 409 衝突測試仍會靜默覆蓋。
- 備份、還原、NetBird、HTTPS、登入或錯誤追蹤不可用。

## 7. 回復流程

```text
停止 API、背景工作與客戶端
        ↓
封存 v2 失敗資料與脫敏診斷
        ↓
驗證切換前備份與 SHA-256
        ↓
還原 PostgreSQL schema 7＋附件庫
        ↓
啟動 v1.8.9 並校正 identity
        ↓
執行健康檢查與 v1 冒煙測試
        ↓
恢復公司 v1.8.2、iPhone v1.8.9、LINE v0.30.0
        ↓
撤銷所有 v2 Token 並公告回復完成
```

回復後不得刪除失敗批次、診斷與 v2 封存資料；它們用於修正下一次演練，但不可重新匯入正式 v1。

## 8. 家中主機尚待完成的實機項目

目前開發工作區已完成規格及測試基線，尚未直接操作家中正式伺服器。第二階段前必須在家中主機執行：

- 建立最新完整備份。
- 複製一份到異地目的地。
- 在隔離 PostgreSQL 還原。
- 核對登入、筆數、關聯及附件雜湊。
- 記錄完成日期、備份檔名及驗收人；紀錄不得包含密碼或 DSN。
