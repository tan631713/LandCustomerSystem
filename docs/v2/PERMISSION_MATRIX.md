# v2.0 權限矩陣

## 1. 符號

- `R`：讀取
- `C`：新增
- `U`：修改
- `D`：刪除／移入回收桶
- `X`：匯出／下載
- `A`：管理、核准或高風險操作
- `—`：不允許

角色權限只是第一層。所有讀寫還必須通過資料範圍、欄位遮罩、資源版本及客戶端類型檢查。

## 2. 系統角色

| 角色 | 說明 |
|---|---|
| Anonymous | 只能取得最小版本能力與登入，不得取得地主或環境細節。 |
| Admin | 管理帳號、權限、備份、稽核、升級與所有業務資料。高風險操作仍限家中主機或明確安全流程。 |
| Editor | 在授權資料範圍內建立及修改業務資料，不可管理帳號、整庫還原、資料金鑰或升級。 |
| Viewer | 唯讀與允許的下載；身分證遮罩；不可新增、修改、刪除或批次匯出敏感欄位。 |
| LINE Basic | 查地主及土地的最小遮罩結果。 |
| LINE Business | Basic 加追蹤、案件及任務摘要。 |
| LINE Full | Business 加受控通知與完成回條；仍不直接修改地主、土地、附件或帳號。 |
| Background Service | 只使用指定服務權限執行排程、備份、完整性掃描及通知投遞，不能互動登入。 |

## 4. 資料範圍

v2 支援三種可組合資料範圍：

- `district`：指定地區。
- `section`：指定地段。
- `project`：指定案件。

同一使用者不同類型範圍採聯集；跨類型採交集。例如「桃園區＋A 案」只可見同時屬於桃園區及 A 案的資料。Admin 預設不受範圍限制，但所有查詢仍寫入稽核摘要。

資料範圍必須在 SQL 查詢及匯出來源層套用，不能只依靠前端隱藏。

## 6. 高風險操作條件

整庫還原、schema 升級、回復、資料重新加密、異地目的地變更及帳號恢復必須同時滿足：

1. Admin。
2. 家中主機或受控維護工作階段。
3. 最近完整備份已驗證。
4. 輸入完整確認文字。
5. 建立升級／維護批次與 Request ID。
6. 成功或失敗均使既有登入工作階段失效。

## 7. LINE 特別限制

- 僅一對一聊天室。
- 不直接使用 Admin／Editor 帳號；後端使用專用最小權限服務身分。
- 不提供匯出、附件原檔、完整地址、完整身分證、帳號、備份或維護功能。
- 最近查詢、分頁、導覽與顯示模式只在 Bot 記憶體短暫保存。
- LINE 綁定資料使用 Bot 獨立加密 SQLite；主系統只接收不透明 principal key。
