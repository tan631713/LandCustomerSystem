土地資料系統 交付說明

建置日期：2026-07-29

本版重點
1. 手機套用新版後會自動回到更新前所在頁面。
2. 今日外勤會恢復原本正在查看的地主，不因行程排序改變而跳錯資料。
3. 持分詳細資料、外勤關聯區段、拜訪動作及安全的行程搜尋內容可一併恢復。
4. 恢復資訊只存在目前分頁並於 15 分鐘後失效。
5. 本批需先更新家中伺服器至 v1.9.22，再更新公司筆電客戶端至 v1.9.0。
6. PostgreSQL 會由 schema 8 升級至 schema 9，只新增關係人資料表與索引；升級前請先完整備份。
7. 回復方式與限制請參閱 docs/OWNER_CONTACTS_PHASE1.md。

正式啟動方式
1. 家中主機：只執行「啟動家中伺服器.bat」，視窗保持開啟。
2. 公司筆電：使用獨立 CompanyLaptopClient ZIP，執行 start_company_laptop_desktop.bat。
3. iPhone 行動版：NetBird Connect 後以 Safari 開啟家中主機的 /mobile/ 網址。
4. iPhone 第一次連線：依「伺服器使用說明.txt」開啟 8733 公開憑證頁並完成信任。

重要提醒
- 「啟動家中伺服器.bat」是伺服器包唯一正式入口；不要開啟 _server_support 或 LandCustomerServer 內部檔案。
- 啟動器會自動檢查 NetBird、PostgreSQL 服務、私人 VPN 防火牆、資料庫連線、HTTPS 與備份；首次設定才會要求 UAC 或 PostgreSQL 管理員密碼。
- 正式 PostgreSQL 模式固定讀取 Windows DPAPI 保護設定，舊的使用者環境連線字串會被安全忽略。
- 請完整保留整個伺服器資料夾，不要只複製 LandCustomerServer.exe。

資料與備份
- PostgreSQL 是 Windows 與 iPhone 唯一共用的正式資料來源；舊 SQLite 不參與同步。
- API 或手機伺服器啟動時會檢查每日 PostgreSQL 壓縮備份。
- 啟動器偵測到既有 PostgreSQL 設定時，會先確認最近 24 小時內有完整備份，再檢查或升級資料結構。
- 若保存的專案連線密碼已失效，啟動器會先要求 PostgreSQL 的 postgres 管理密碼來修復專案帳號，修復後重新建立完整備份；仍失敗才安全停止。
- 啟動器每 24 小時自動建立備份；備份包含 PostgreSQL dump、manifest 與納管附件。
- 備份預設放在 %LOCALAPPDATA%\LandCustomerSystem\postgres-backups，保留 90 天、最多 30 份且至少保留 3 份。

v1.9.11 外勤模式第 16 批－附件刪除權限
- Editor 只能刪除自己上傳的附件，Admin 可刪除全部附件，Viewer 維持唯讀。
- 手機是否顯示刪除按鈕，完全依伺服器回傳的 can_delete 判定，不信任前端自行判斷。
- API 不會把附件上傳者的內部帳號 ID 傳到手機，只回傳能否刪除。
- 舊附件若沒有上傳者紀錄，為避免誤刪，只有 Admin 可以刪除。
- PostgreSQL 刪除時會先鎖定並再次檢查附件，再於同一交易完成刪除與稽核紀錄。
- 單機相容資料庫會自動補上附件上傳者欄位，新上傳附件會保存登入者身分。
- 手機快取版本已更新；安裝新版伺服器後重新整理手機頁面即可生效。

- 家中伺服器啟動視窗會顯示相同指紋；公開 CA 下載未傳送任何地主或土地資料。

v1.7.9 遠端更新與修改歷史交易修正
- 公司筆電更新資料與寫入修改歷史改為家中 PostgreSQL 的同一交易，不會先改成功再顯示 500。
- 同一筆資料一次修改多個欄位時，伺服器會先去除重複 ID，再正確驗證與寫入所有歷史。
- 任一步驟失敗會完整回滾；家中伺服器與公司筆電客戶端必須一併更新至 v1.7.9。

v1.7.8 首次搬移歷史殘留判斷修正
- 刪除測試持分後留下的孤立 owners／lands、回收桶與操作歷史不再被誤判成有效正式資料。
- 只有有效持分、案件、附件與其關聯會阻擋首次搬移；孤立 owners／lands 於搬移交易內清除。
- 回收桶與操作紀錄保留，匯入前 PostgreSQL 完整備份、失敗回滾及伺服器帳號保護維持不變。

v1.7.7 單機資料安全搬移
- `.lcs-migration.zip` 內是完整且仍加密的 SQLite 一致性快照，附資料表筆數、大小與 SHA-256 清單。
- 唯一伺服器啟動檔會偵測搬移包；驗證單機帳號及伺服器 admin 後，先備份再匯入。
- 資料改用伺服器共用金鑰重新加密，伺服器 users 與 admin 密碼不會被來源覆蓋。
- 只接受空的家中業務資料庫；重複匯入、筆數不符、孤兒關聯、損壞檔或含附件時安全停止。

v1.7.6 缺少 admin 帳號時的安全恢復
- 離線恢復在資料庫沒有 admin 時會建立完整管理員帳號；已有 admin 時維持重設密碼流程。
- 建立與重設都必須先驗證目前有效帳號密碼及既有資料金鑰，並使用單一交易。

v1.7.5 家中主機離線恢復 admin 密碼
- 在唯一啟動檔旁放置 recover-admin-password.request 才會啟用，不對手機或公司筆電提供遠端端點。
- 先驗證目前可登入帳號密碼及既有資料金鑰，再要求輸入兩次新 admin 密碼。
- 成功時只更新 admin 的密碼雜湊與資料金鑰包裝並寫入操作紀錄；業務資料保持不變。

v1.7.4 安全帳號恢復
- 已登入單機版可匯出單一 `.lcs-account`，檔案不含明碼密碼與明碼資料金鑰。
- 家中伺服器唯一啟動檔會偵測恢復檔，在本機驗證新密碼及既有加密資料後，只新增登入帳號。
