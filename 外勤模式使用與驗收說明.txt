土地資料系統 2.0－手機 Web 外勤模式使用與驗收說明
==================================================

適用版本
--------
家中伺服器：v1.9.21
公司筆電：v1.8.6
資料庫：PostgreSQL schema 8

正式使用方式
------------
1. 家中主機只執行「啟動家中伺服器.bat」，並保持視窗開啟。
2. iPhone 或 Android 先連線 NetBird，再以瀏覽器開啟伺服器顯示的 /mobile/ 網址。
3. 公司筆電執行客戶端內的 start_company_laptop_desktop.bat。
4. 手機與公司筆電必須登入同一台家中伺服器；兩端不建立獨立外勤資料庫。
5. 手機登入頁顯示「網路伺服器可以使用」後再登入；若顯示異常，依畫面提示確認網路、NetBird 或家中主機，再按「重新檢查連線」。
6. 手機顯示「手機網頁有新版」時按「立即更新」；系統會重新載入並顯示更新完成，不需自行清除 Safari 快取。
7. 若正在上傳附件、尚有檔案或行程調整未儲存，請依提示先完成；也可按「稍後」延後到現場工作結束後更新。
8. 安全套用新版後，確認畫面回到原頁面、原行程地主或原本開啟的持分詳細資料。

完整操作流程
------------
1. 在手機或公司筆電搜尋地主，加入指定日期的今日行程。
2. 開啟今日外勤，確認總數、完成、未完成、略過及預估距離。
3. 按「開始外勤」，允許瀏覽器取得目前位置。
4. 檢查路線預覽，確認後才套用新的拜訪順序。
5. 目前地主可直接導航、撥號、新增聯絡紀錄或上傳照片。
6. 抵達後按開始拜訪；結束時選擇完成、略過或延後。
7. 行程改變時按重新規劃，只重排尚未完成的地主。
8. 完成最後一位後檢查整日成果摘要。
9. 回到公司筆電，在同一筆地主資料開啟出訪紀錄及附件，確認手機資料已同步。

手動驗收清單
------------
[ ] 手機可登入並開啟今日行程。
[ ] 可加入至少三位不同地主，重複加入不會建立兩筆。
[ ] GPS 成功時可預覽順序；拒絕定位時可沿用原順序並重新取得定位。
[ ] 優先地主先於一般地主；人工固定順位不會被無提示覆蓋。
[ ] 導航可直接開啟 Google Maps，不需複製地址。
[ ] 完成、略過、延後及取消均顯示正確狀態。
[ ] 網路中斷時未送出的備註、聯絡紀錄及附件會保留並可重送。
[ ] 現場新增的聯絡紀錄與照片會標示為本次行程。
[ ] Editor 只能刪除自己上傳的附件，Admin 可刪除全部，Viewer 只能查看。
[ ] 公司筆電能讀到手機新增的聯絡紀錄與附件。
[ ] 全部處理後會顯示行程完成摘要。

自動驗收範圍
------------
- 正式打包前強制執行完整旅程測試。
- 自動流程包含登入、建立行程、三位地主、GPS 排序、預覽確認、開始拜訪、
  聯絡紀錄、照片上傳、完成、略過、剩餘路線重排、整日完成及桌面讀回。
- 另有 10、100、1,000 位地主的路線容量與完整性測試。
- 任一必要驗收失敗，正式伺服器 ZIP 不會產生。

已知限制
--------
- 第一階段依 Haversine 直線距離與最近鄰居法排序，不包含即時交通路況。
- 不串接付費 Google Routes API；Google Maps 只負責開啟導航。
- 不提供完整離線資料庫、背景 GPS、自動抵達或自動簽到。
- 地址未提前保存有效座標時會以地址導航；地址也空白時不能導航。
- 家中主機關機、伺服器視窗關閉、PostgreSQL 停止或 NetBird 未連線時，手機與公司筆電無法同步。

資料與安全
----------
- 正式資料只儲存在家中 PostgreSQL；手機不保存另一份正式資料庫。
- GPS 只在行程狀態歷史或聯絡紀錄需要時保存，不做背景持續追蹤。
- 所有寫入由伺服器驗證登入、角色、資料歸屬與輸入內容。
- 狀態、排序、附件與聯絡紀錄均使用防重複識別或交易保護。
- 照片存於家中伺服器附件庫，PostgreSQL 保存中繼資料、雜湊與關聯。

更新與回滾
----------
1. 更新前先關閉舊伺服器，確認最近一次完整備份正常。
2. 將新版 ZIP 解壓到新的資料夾，不要直接刪除舊版資料夾。
3. 執行新版唯一啟動檔並完成手機、公司筆電及本說明的手動驗收。
4. 本版沒有資料庫 migration；若需回滾，關閉新版後重新開啟舊版唯一啟動檔即可。
5. 不要手動複製、覆蓋或刪除 PostgreSQL 資料目錄。
6. 若資料本身需要還原，使用系統備份管理功能，不要以舊程式資料夾取代資料庫。
